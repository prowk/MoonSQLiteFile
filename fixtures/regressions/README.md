# 历史 fuzz 边界回归

这些输入来自本地历史失败样本，种子为 20261003。原失败发生在 fuzz 的范围/故障报告差分断言中；当前实现重放已经通过。这里保存边界数据和预期分类，不声称当前仍能复现旧 panic，也不将受控 Invalid/Unsupported 当作崩溃。

| 输入 | 原规模 → 保留规模 | 保留的路径 |
| --- | --- | --- |
| range-fault-two-pages | 1024 → 1024 字节 | 两个完整 512 字节页；UTF-16LE schema 与对象读取、范围源/旧源/缓存/故障报告。保留原输入，未宣称最少字节变更。 |
| wal-large-commit | 1640 → 1104 字节 | 删除提交后的一个未提交帧，保留完整两帧 checksum 链及异常大逻辑页数提交；主文件单独保留。 |
| truncated-magic | 93 → 16 字节 | 保留完整 SQLite magic，删除其后仍不足 100 字节的头；旧源与范围源的初始化分类边界。 |

每个 JSON 记录原 SHA、种子、迭代位置、原/当前长度、重放页号和预期分类；当前 SHA 覆盖 WAL 与配对主文件。最小化指上述边界性质下的缩减，不保证全局最小，也不靠字符串匹配隐藏新的异常。执行 `python tools/verify_regressions.py` 重放全部输入；同一差分入口继续比较旧源、范围源、适配器、缓存和读取故障。
